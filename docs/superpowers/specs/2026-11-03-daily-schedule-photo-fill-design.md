# 일일 일정표 — 손글씨 노트 사진으로 칸 채우기 (설계)

2026-11-03 사무실 PC. 사장님 결정: B 방법(클로드가 읽음, 버셀 서버 기능) · 오퍼스 5.5 · 앤트로픽 월 한도 1만 원 · 지금 연 일정표에 채우기 · 만들기는 관리자에게.

## 1. 왜 · 지금은 어떻게 하나

- 지금: 사장님이 다음 날 일을 **손글씨 노트**에 적고(번호 · 장소 · 시간 · 고인/상주 · 전화 · 금액 · 오른쪽에 담당), 저녁에 휴대폰으로 `daily-schedule.html` 을 열어 칸마다 다시 친다.
- 없애고 싶은 단계: **다시 치기**(특히 전화번호 · 금액). 읽은 뒤 확인 · 고치기는 남는다(사장님이 알고 고름 — 시험 사진에서 이름 · 장소는 절반쯤 추측, 전화번호 한 자리가 흔들림).
- 성공 기준: 사장님 휴대폰에서 노트를 찍으면 **1분 안에** 칸이 채워지고, 자신 없는 칸은 노란색, 고친 뒤 저장 · 직원에게 보내기가 지금처럼 된다.

## 2. 실제 데이터 (2026-11-03, 읽기만 · 건수만)

일정표 13장 · 채운 줄 53. 한 장 2~11줄(보통 4).
칸마다 채운 줄: 담당 · 시간 · 장소 53/53, 메모 47, 행사 내용 42, 단가 33, 연락처 28, 상조팀장 23, 출발 20, 팀장 전화 18, 차량 17, 장례식장 16, 화장 11, 발인 5, 인원 2, 현지 안내인 전화 0.
→ AI 가 꼭 잘 채울 칸: 담당 · 시간 · 장소 · 내용 · 연락처 · 단가 · 메모 + 장례 칸(상조팀장 · 팀장 전화 · 장례식장 · 화장 · 발인).

시험 사진 한 장(사장님 노트, 11-04 일 5건)에서 본 모양: 위쪽에 담당자 번호표(②박○○ ③최○○ …), 일마다 번호 · 장소 · 시간 · "고인 ○○○" · "상주 010-…" · 상조회사 + 팀장 이름 · 전화 · "○○ 화장 8시" · 금액("35만", "60명×15,000"), 오른쪽 끝에 담당 이름. 사진은 저장소에 두지 않는다(손님 개인정보).

## 3. 구조

```
휴대폰 일정표(편집 중) ─ 사진 + 로그인 표(ID 토큰) + 이름 목록 ─▶ foodbell.kr/api/read-note (버셀 서버 기능)
                                                                    │ ① 표로 허락 목록(allow/{메일}) 읽기 → 주인인지
                                                                    │ ② 클로드 오퍼스 5.5 (사진 + 지시 + 이름 목록)
                         ◀── 줄마다 칸 값(JSON) + 자신 없는 칸 목록 ──┘
화면이 빈 줄부터 채움 · 노란 표시 → 사장님이 고침 → 저장(지금 그대로)
```

### 3-1. 서버 기능 `api/read-note.js` (새 파일)

- 버셀 Node 서버 기능. 저장소 맨 위에 `package.json`(의존: `@anthropic-ai/sdk` 하나)을 새로 둔다. `node_modules/` 는 `.gitignore`.
- **GET** → `{ ready: true|false }` — 버셀에 `ANTHROPIC_API_KEY` 가 들어 있는지만. 로그인 없이 답한다(값은 안 알려 줌).
- **POST** → 몸통 `{ image: <base64 JPEG>, hints: { places: [...], staff: [...] }, day: 'YYYY-MM-DD' }`, 머리 `Authorization: Bearer <파이어베이스 ID 토큰>`.
  1. 토큰이 없으면 401.
  2. **주인 확인**: 사장님 토큰 그대로 Firestore REST 로 `allow/{토큰의 메일}` 문서를 GET. 지금 보안 규칙이 "자기 메일 문서만 get"(firestore.rules 25-26줄, 2026-11-03 확인) → 200 이면 주인, 403/404 면 403 으로 거절. 토큰 검사는 Firestore 가 한다 — 서버에 따로 서명 확인 부품을 두지 않는다. 프로젝트는 실제(`foodbell-sije`) 하나.
  3. 사진이 너무 크면(몸통 4MB 넘음) 413.
  4. 클로드 호출 → 결과를 그대로 돌려줌(200).
- 사진 · 결과 · 메일을 **기록(console)에 남기지 않는다** — 상태 숫자 · 걸린 시간 · 토큰 수(비용 계산용 숫자)만.
- 버셀 설정의 비밀값: `ANTHROPIC_API_KEY` (사장님이 넣음). 코드 · 저장소 · 문서에 값을 쓰지 않는다.

### 3-2. 클로드 지시

- 모델 `claude-opus-5-5`(사장님 결정), 생각은 기본(adaptive), `output_config.effort` = `medium` 으로 시작 → 실제 사진 시험에서 정확도 · 시간을 보고 `high` 가 필요한지 정한다(4절).
- 거절 대비: 서버 측 대체(`fallbacks: "default"`, beta `server-side-fallback-2026-07-01`)를 켠다 — 안전 판단으로 거절되면 다른 모델이 이어 읽는다(claude-api 스킬 기본값). 끄려면 두 줄 지우면 된다.
- 결과는 **구조화 출력**(`output_config.format` JSON 스키마)으로 받는다:
  ```
  { "day": "YYYY-MM-DD" 또는 "",          // 노트에 적힌 날짜 (없으면 "")
    "rows": [ { "staff","car","leave","time","place","tel","work","people","price",
                "lead","lead_tel","hall","depart","cremate","memo": 문자열(없으면 ""),
                "unsure": [자신 없는 칸 이름들] } ],
    "note": "어느 칸에도 못 넣은 글" }
  ```
- 칸 규칙(지시문에 넣음): 시간 `HH:MM`(14시 → 14:00, 9시40 → 09:40) · 전화 `010-1234-5678`, 여럿이면 ` / `, 누구 번호인지 앞에(상주 010-… ) · 단가는 적힌 그대로("35만", "15,000") · "60명×15,000" 은 인원 60 · 단가 15,000 · 담당은 오른쪽 끝 이름과 위쪽 번호표 · 상조팀장은 "회사 + 이름"(○○상조 ○○○ — 실제 회사 이름을 예시로 쓰면 흐린 글씨를 그쪽으로 읽을 수 있어 바꿈, 11-03 사장님) · 장례식장 · 화장장은 hall, 화장 · 발인 시각은 cremate · depart · 나머지(고인 이름, 밥 1개, 위치 메모 등)는 work 또는 memo.
- **이름 목록(hints)**: 장소 · 담당은 목록에 있는 이름과 비슷하면 목록 글자로 쓴다. 목록에 없으면 읽은 그대로 + `unsure`.
- 읽기 애매한 글자 · 숫자가 있는 칸은 반드시 `unsure` 에 넣는다. 지어내지 않는다(빈칸이 낫다).

### 3-3. 화면 (`daily-schedule.html`)

- 단추 "사진으로 채우기" — **편집 중 + 주인(owner) + GET 이 ready:true** 일 때만, "줄 추가 (일 하나)" 옆 줄에. 열쇠를 넣기 전에는 안 보인다.
- 누르면 `<input type=file accept="image/*">`(휴대폰은 카메라 · 사진첩 고르기). 받은 사진은 화면에서 **긴 변 2000점 JPEG** 로 줄여 보낸다(4MB 넘으면 더 줄임). "읽는 중… (최대 1분)" 표시, 그동안 단추 막음.
- 채우기: **모든 칸이 빈 줄**부터 차례로 채우고, 모자라면 "줄 추가"와 같은 방법으로 줄을 더한다. 글자가 있는 줄은 건드리지 않는다. 칸을 넣은 뒤 칸을 떠날 때 하는 정리(전화 모양 `js/docs/phone.js`, 금액 읽기 `readNumber`)를 같은 함수로 한 번 돌리고, 금액 · 합계 다시 계산, 장례 칸에 글자가 있으면 펼친다, 저장 알림(`save()`).
- 노란 표시: `unsure` 칸에 `ai-unsure` 표시(노란 바탕). 그 칸을 고치면 사라진다. **저장 HTML · 직원 사진(카드) · 인쇄 · 직원 게시판에 나오지 않는다**(serialize 에서 지움, 인쇄 css 에서 뺌).
- 날짜: 결과 `day` 가 일정표 날짜와 다르면 알림 한 줄("노트 날짜 11/4 · 일정표 날짜 11/5 — 확인하세요"). 일정표 날짜는 바꾸지 않는다.
- `note` 가 있으면 알림으로 보여 준다(칸에 안 넣음).
- 이름 목록: 이 기기가 이미 받은 일정표 목록(공통 부품 `js/docs/doc-page.js` 의 목록 — 최근 고친 순 20장까지)에서 담당 · 장소 글자를 모은다(각 60개까지). 손님 이름 · 전화는 보내지 않는다.
- ID 토큰: `js/sije/store.js` 에 로그인한 사람의 토큰을 주는 함수 하나를 더한다(화면은 파이어베이스를 직접 부르지 않는 지금 규칙 그대로).
- 실패 알림(한 줄): 401 "로그인이 풀렸습니다 — 다시 로그인해 주세요" · 403 "이 계정은 쓸 수 없습니다" · 413 "사진이 너무 큽니다" · 한도 · 결제 오류 "이번 달 사용 한도에 닿았습니다(앤트로픽 설정 확인)" · 시간 초과 "시간이 너무 걸렸습니다 — 다시 눌러 주세요" · 그 밖 "사진을 읽지 못했습니다 (번호)". 실패해도 일정표는 그대로.

### 3-4. 같이 고칠 곳

- `sw.js`: `/api/` 는 저장하지 않고 통과(지금은 같은 사이트 GET 을 "저장된 것 먼저"로 줘서 ready:false 가 굳을 수 있다 — 2026-11-03 확인, 136줄) + `CACHE` 번호 올림.
- 캐시 번호(`?v=`): 고친 js 를 부르는 곳.

## 7. 범위 밖

- 휴대폰 밖(PC 대화)에서 사진 → 일정표(②)는 만들지 않는다.
- 일정표 날짜 · 순번 · 전달 메모는 사진으로 바꾸지 않는다.
- 사진 보관 · 읽기 기록 보관 없음. 일정표 말고 다른 서류(견적서 등)에는 붙이지 않는다.
- 제미나이 · 무료 방식(A)은 쓰지 않는다(손님 개인정보).
