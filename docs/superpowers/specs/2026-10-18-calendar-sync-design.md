# 시제행사 → 구글 캘린더 자동 맞추기 설계 (2026-10-18)

사장님과 대화로 정한 것(사무실 PC). 이 문서가 확인되면 작업 계획 → 만들기로 넘어간다.

## 목적

시제행사 목록(파이어베이스 `events`)의 행사를 사장님 구글 캘린더에 **저절로, 계속** 맞춰 넣는다.
휴대폰 캘린더에서 행사 일정이 바로 보이게 하는 것이 목적이다. 고치는 곳은 목록(내역서) 하나 — 캘린더는 보기용.

## 사장님이 정한 것

| 항목 | 결정 |
| --- | --- |
| 넣는 방식 | 계속 저절로 맞추기 (한 번 옮기기 아님) |
| 넣을 행사 | 확정 + 미확정(날짜 있는 것만). 주문없음은 넣지 않고, 주문없음으로 바뀌면 지운다 |
| 캘린더 | 새 캘린더 **"푸드벨 행사"** (사장님 계정 소유) |
| 일정 메모 | 고객 이름 · 연락처 · 금액 · 내역서 바로가기. (출발 · 도착 · 담당 · 차량은 넣지 않음) |
| 연결 방법 | 사무실 PC 예약 작업("푸드벨 시제 PDF")에 붙이고, 서버용 계정(관리자 열쇠)으로 쓴다. gws 는 7일마다 로그인이 풀려서 쓰지 않는다 |
| 캘린더 만들기 · 공유 | 클로드가 gws(사장님 로그인)로 만들고 서버용 계정에 공유 |

## 캘린더에 보이는 모습

- 행사 하나 = 일정 하나.
- **제목**: `장소 · 상차림` (장소 = `place`, 비었으면 `titlePlace`; 상차림 = `setting`, 비었으면 장소만; 둘 다 비면 `시제행사`).
  미확정이면 앞에 `[미확정]` + 빈칸 하나.
- **장소 칸(location)**: 위와 같은 장소 — 휴대폰에서 누르면 지도.
- **시간**: `time` 칸을 읽는다. 적힌 숫자 그대로(24시간제처럼): `10시` → 10:00, `9시 30분` → 9:30, `5시` → 05:00, `13시` → 13:00.
  `오전 N시` / `오후 N시`도 읽는다(오후는 12를 더함, `오후 12시` = 12:00, `오전 12시` = 00:00). 비었거나 못 읽으면 **종일** 일정.
  끝 = 시작 + 2시간 (추정 — 자료에 행사 길이 없음). 시간대 Asia/Seoul.
- **메모(description)**: 줄마다 `고객: …` / `연락처: …`(여러 개면 쉼표) / `금액: …`(적힌 글자 그대로) /
  `내역서: https://foodbell.kr/sije-sheet.html?id=<행사 번호>`. 빈 칸은 줄째 뺀다.
- **색**: 확정 = 캘린더 기본색, 미확정 = 회색(colorId 8).
- 지난 행사(2025-11~)도 모두 넣는다. 알림은 따로 넣지 않는다(캘린더 기본 설정).
- **한쪽 방향**: 목록 → 캘린더. 캘린더에서 고친 것은 다음 차례에 목록 내용으로 되돌아간다.

실제 자료(2026-10-18, 85개): 확정 65 · 미확정 16 · 주문없음 4, 날짜 없음 1.
시간 칸 모양: `10시` 38 · 빈칸 18 · `11시` 14 · `8시` 4 · `9시` 3 · `12시` 2 · `13시` 2 · `14시` · `7시` · `9시 30분` · `5시`.

## 돌아가는 방식

### 처음 한 번 (준비)

1. gws 로 사장님 계정에 "푸드벨 행사" 캘린더를 만들고, 서버용 계정
   `firebase-adminsdk-fbsvc@foodbell-sije.iam.gserviceaccount.com` 에 **일정 변경(writer)** 으로 공유.
2. 서류용 프로젝트 `foodbell-sije` 에서 Google Calendar API 사용 설정 — 사장님이 콘솔 링크에서 한 번 누름.
3. 시험용: `foodbell-sije-test` 프로젝트도 Calendar API 사용 설정 + "푸드벨 행사(시험)" 캘린더를 시험 서버용 계정에 공유.
4. 캘린더 주소(캘린더 ID)는 열쇠 폴더의 텍스트 파일에 둔다 — 저장소에는 넣지 않는다.
   실제 `C:\foodbell-keys\sije-calendar.txt`, 시험 `C:\foodbell-keys\sije-test-calendar.txt`.
   파일이 없는 PC(집 · 노트북)에서는 캘린더 단계를 조용히 건너뛴다.

**첫 단계에서 먼저 확인할 것(추정)**: 지메일 개인 계정 캘린더를 서버용 계정에 공유하면 그 계정이 일정을 쓸 수 있다.
안 되면 멈추고 사장님께 다시 묻는다.

### 사무실 PC 프로그램

- **새 파일 `tools/sije_web/calendar_sync.py`**
  - `to_calendar_event(id, ev) -> dict | None` — 위 규칙대로 일정 모양을 만든다. 넣지 않을 행사(주문없음 · 날짜 없음 · 상태가 확정/미확정이 아님)는 `None`.
    인터넷 없이 시험할 수 있는 순수 함수.
  - 일정 번호는 행사 번호에서 고정으로 만든다(캘린더 일정 ID 규칙: 소문자 a–v · 숫자 — 행사 번호를 16진수로 바꿔 앞에 `fb`).
    같은 행사가 두 번 들어가지 않고, 따로 상태 파일이 필요 없다.
    구글은 지운 일정의 번호를 다시 만들 수 없게 한다(409) — 지웠던 행사가 다시 필요해지면(주문없음 → 확정)
    같은 번호의 지워진 일정을 고치기(`status: confirmed`)로 되살린다.
  - 일정마다 숨은 꼬리표(`extendedProperties.private.foodbellId`)를 단다. 맞추기는 **꼬리표 있는 일정만** 다룬다.
  - `sync_calendar(cal, events) -> {made, updated, removed, failed}` — 캘린더의 꼬리표 일정 전체와 행사 전체를 비교해
    빠진 것 만들기 · 달라진 것 고치기 · 남는 것 지우기. `cal` 은 캘린더와 말하는 작은 부품(목록 · 만들기 · 고치기 · 지우기)이라
    시험에서는 가짜로 바꿔 끼운다.
  - 구글 연결: 관리자 열쇠(서비스 계정)로 `google.oauth2.service_account` + `google.auth.transport.requests.AuthorizedSession`
    (firebase-admin 에 이미 들어 있음 — 새로 설치하는 꾸러미 없음). 범위 `https://www.googleapis.com/auth/calendar.events`.
- **`office_agent.py`**: `one_cycle` 에 세 번째 덩어리로 캘린더 맞추기를 넣는다. PDF · 백업과 따로 `try` 로 감싼다.
  매 차례(5분) 전체 비교. 기록(`agent.log`)에는 바뀐 것만: `캘린더 만듦/고침/지움: <제목>`, 실패는 경고.
- 고친 코드를 받은 뒤 예약 작업 "푸드벨 시제 PDF" 를 **껐다 켠다** — 상주 프로그램이라 옛 코드를 들고 있다.

## 잘못될 때

- 인터넷 끊김 · 구글 오류: 그 차례 건너뛰고 기록, 5분 뒤 다시. PDF · 백업은 계속.
- 권한 없음(공유 풀림, 403/404): `캘린더 권한 없음` 경고를 남기고 계속.
- 시간 칸을 못 읽음: 종일 일정.
- **한꺼번에 지우기 방지**: 행사 목록이 0개로 읽히면 "목록을 못 읽은 것"으로 보고 그 차례에는 아무것도 지우지 않는다(경고 기록).
- 꼬리표 없는 일정(사장님이 손으로 만든 것)은 절대 건드리지 않는다.
- 일정 하나가 실패해도 나머지는 계속하고, 실패한 것은 다음 차례에 다시.

## 시험

1. **바꾸기 규칙** (pytest, 인터넷 없음): 위 실제 시간 모양 11가지 + `오전 10시` · `오후 2시` · `오후 12시` + 빈칸 · 못 읽는 글자.
   미확정 표시 · 회색, 주문없음/날짜 없음 → `None`, 메모 줄(빈 칸 빠짐), 제목의 장소 대체(`titlePlace`), 일정 번호 규칙.
2. **맞추기** (가짜 캘린더): 만들기 · 고치기 · 지우기 · 두 번 돌리면 두 번째는 아무것도 안 함 · 목록 0개면 안 지움 ·
   꼬리표 없는 일정 안 건드림 · 하나 실패해도 나머지 진행 · 지웠던 행사가 다시 확정되면 되살림.
3. **진짜 구글** (시험 프로젝트 + "푸드벨 행사(시험)"): 가짜 행사 하나로 만들기 → 고치기 → 지우기를 실제로.
4. **마지막**: 실제로 한 번 돌린 뒤 사장님이 휴대폰 캘린더에서 확인(예: 3월 1일 행사).

## 성공 기준

- 확정 · 미확정(날짜 있음) 행사가 모두 "푸드벨 행사" 캘린더에 위 모양으로 들어간다.
- 목록에서 날짜를 고치면 사무실 PC 가 켜져 있을 때 5분 안에 캘린더도 바뀐다. 주문없음으로 바꾸면 사라진다.
- 위 시험 1~3 이 모두 통과하고, 기존 시험도 그대로 통과한다.

## 하지 않는 것

- 캘린더 → 목록 방향 반영, 알림 넣기, 출발 · 도착 · 담당 · 차량 넣기, 직원 공유(나중에 사장님이 캘린더 공유만 하면 됨).
- 드라이브 사진 정리 — 별도 작업으로 따로 정한다.
