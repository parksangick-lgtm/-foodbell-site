### 공식 설명서에서 확인한 것 (10-28)

- 도우미는 도우미를 부를 수 있다 — 기본 **3단까지**(`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`). 메인 → 관리자 → 일꾼은 2단.
- 도우미는 **질문 창(`AskUserQuestion`)을 못 쓴다** — 첫 거르기에서 빠지는 도구 목록에 있다. 그래서 사장님께 여쭐 일은 관리자가 메인에게 넘긴다.
- VS Code 에서 메인이 부른 도우미는 **기본으로 뒤에서(백그라운드) 돈다** — 메인 차례가 끝나면 자동 저장이 도우미가 반쯤 고친 파일을 올린다.
  기다리려면 `CLAUDE_CODE_FORK_SUBAGENT=0` 을 넣고 새 대화를 연다.
- 뒤에서 도는 도우미도 `Agent`(도우미 부르기) · `Bash` · `Edit` · `Write` · `Read` 를 쓸 수 있다(3단 한계에 닿지 않으면).
- 도우미 안에서 부른 도우미는 부른 쪽이 보고를 기다린다(대화형 세션).
- `Agent(이름, 이름)` 으로 부를 수 있는 도우미를 묶는 것은 **대화 자체가 관리자일 때(`claude --agent`)만** 먹는다 — 도우미 파일에서는 괄호 안이 무시된다.

3. 관리자가 시작 상태(`git status --short`)를 적고 일을 표로 나눈다. 서로 다른 파일이면 고치기 담당 여럿을 **동시에**.

7. 답이 끝나면 자동 저장으로 올라가고, **다음 차례에** 배포 확인 담당이 서버를 확인한다(올라간 뒤에야 확인할 수 있으므로).
   관리자는 자기가 고친 것의 배포 확인을 같은 실행 안에서 하지 않는다 — 그 안에서는 늘 "다름"으로 나온다.

## 지침 — 모든 도우미 공통

- 보고와 **명령 설명은 한국어로**(가정 2). 명령 · 파일 이름 · 오류 원문만 영어 그대로.
- 임시 파일 · 사진은 **작업 폴더가 아니라 `%TEMP%`** 에 — 작업 폴더에 두면 자동 저장으로 foodbell.kr 에 공개된다.
- 손님 이름 · 연락처 · 열쇠 파일 내용은 찍지 않는다. 셀 때는 **건수만**.
- 파이썬은 `python -X utf8`.
- 사이트 작업 흐름 스킬(`~/.claude/skills/foodbell-site-dev/SKILL.md`)은 통째로 읽지 않고 **맡은 일의 절만** 읽는다
  (`grep -n '^#'` 로 목차를 보고 그 줄부터).
- 확인한 것과 못 한 것을 나눠 적는다. 못 한 것은 "확인 못 함" 이라고 쓴다.

## 지침 — 도우미별 핵심 규칙

**관리자**
- 시작 때 `git status --short` 를 적어 둔다 — 원래 바뀌어 있던 것과 이번에 바꾼 것을 가르려고.
- 일꾼은 이 대화를 모른다 → 맡길 때 **목적 · 파일 · 끝난 기준**을 지시문에 적는다.
- 고치기 담당은 **파일이 겹치지 않을 때만** 동시에. 겹치면 차례로.
- 확인 범위는 고친 크기에 맞춘다(시험 담당 규칙의 표) — 작은 수정에 전체 시험을 돌리지 않는다.
- 이 설계의 일꾼 여섯(`foodbell-*` 다섯 + `content-reviewer`)만 부른다.
- 실패 → 다시 고치기는 두 바퀴까지. 위 금지 목록은 하지 않고 여쭐 것으로.

**고치기 담당**
- 맡은 파일 · 맡은 곳만. "하는 김에" 고치지 않고, 원래 이름 · 모양을 따른다.
- 화면 규칙: 값은 `css/style.css` `:root` 에서만, 글자 굵기 세 단계, 누르는 자리 44px · 글자 14px, 이모지 · 특수문자 아이콘 금지(선 아이콘 SVG),
  가격 금지, 사이트에 없는 사실 지어내지 않기(CLAUDE.md "화면 만들 때" · "내용 규칙").
- 버그는 먼저 실패하는 시험으로 다시 일으키고 → 고치고 → 통과를 본다.
- css/js 를 고치면 그 파일을 부르는 화면의 `?v=` 를 올린다(`python 캐시버전올리기.py --check`, 스킬 1절).
- 보고: 바꾼 파일과 곳, 돌린 시험, 남은 걱정.

**시험 담당**
- 범위는 고친 크기로(스킬 2절 "서류 시험(pytest)을 돌리고 읽기" 표): 화면 하나 = 그 시험 + `-k` (1분 안쪽),
  공용 부품(`js/docs/*` · `css/docs.css` · 시험 도우미) = 그 파일 전체나 시험 전체(15분쯤), 문서만 = 부르는 곳 0 + JS 시험(14초).
- 명령: `python -X utf8 -m pytest tools/sije_web/tests -q`, `node --test tools/sije_web/js-tests/*.test.mjs`
  (폴더 이름만 주면 0개 돌고 '실패 1' 로 나온다).
- 하나만 실패하고 혼자 돌리면 통과해도 **네 단계**(다시 · 기다림 늘리기 · CPU 느리게 · 같은 일 하는 화면과 비교) 뒤에야 '일시'로 적는다.
- 노트북의 '새 서류' 시간 초과는 알려진 문제(기록장 #84)라고 표시한다.
- 서류 시험은 시험 열쇠가 있는 PC(사무실 · 노트북)에서만 돈다 — 없으면 "못 돌림".
- 보고: 통과 · 실패 · 건너뜀 숫자, 실패마다 원인 한 줄과 판정(진짜 / 일시).

**휴대폰 화면 확인**
- `python -X utf8 휴대폰캡처.py` (스킬 2절). 결과 표에서 **폭이 390 인지 숫자로 먼저** 본다 — "★측정 실패"면 그 사진으로 판단하지 않는다.
- 넘침 0 · 누르는 자리 44px · 글자 14px. 사진은 직접 열어 눈으로 본다.
- "깨졌다"고 하기 전에 도구가 그 조건을 정말 만들었는지 숫자로 증명한다(헤드리스 크롬 `--window-size` 485px 사건).
- 로그인이 필요한 서류는 미리보기에서 가짜 계정으로 찍힌다 — 실제 내용은 foodbell.kr 에서(스킬 2절 "로그인이 필요한 서류").

**코드 규칙 검토**
- 대상은 바뀐 곳(`git diff`, 새 파일은 전체)만.

**배포 확인**
- 먼저 `git status -sb` 에 `ahead` 가 없는지(안 올라갔으면 서버가 다른 게 당연).
- 스킬 4절 명령: `foodbell.kr` 200, www · 한글 주소 308, 캐시 번호 내 컴퓨터 = 서버. 고친 파일마다 서버 것과 비교,
  글자만 바꾼 것은 그 문구를 직접 찾고, 지운 것은 지운 것 자체를 찾는다.
- "손님 화면에 반영됐다"가 아니라 **"서버에 올라갔다"** 고 쓴다(서비스워커가 옛 화면을 붙잡을 수 있음).

**문구 검토** — 지침은 그대로. 설명 줄만 "…라고 할 때, 또는 관리자(`foodbell-manager`)가 부를 때 쓴다" 로.

## 확인 방법 (만든 뒤)

원칙: 도우미마다 **잡아야 할 것을 잡는지**(문제가 있는 것)와 **멀쩡한 것에 조용한지**(문제없는 것)를 둘 다,
결과는 메인이 직접 돌린 숫자와 대조. 시험용 가짜 파일은 모두 **저장소 밖 `%TEMP%`** 에.

**시험 1. 파일 모양**(이 대화에서) — 7개 머리말(이름 · 설명 · 도구 · 모델)이 읽히는지, 읽기만 하는 도우미에 Edit · Write 가 없는지,
일꾼 여섯에 `Agent` 가 없는지, 설정 파일이 JSON 으로 읽히는지.

**시험 2. 일꾼 하나씩**(이 대화에서)

| 일꾼 | 문제를 줌 → 잡아야 함 | 멀쩡한 것을 줌 → 조용해야 함 |
| --- | --- | --- |
| 시험 담당 | `%TEMP%` 의 일부러 실패하는 가짜 시험 → "실패 1" | JS 시험 → 메인이 직접 돌린 통과 숫자와 같음 |
| 휴대폰 화면 확인 | 일부러 넘치게 만든 가짜 쪽 → "넘침 1" | 첫 화면 → 폭 390 · 넘침 0 |
| 코드 규칙 검토 | 가짜 변경에 이모지 아이콘 · 즉석 색 · '30만원' → 셋 다 | 규칙에 맞는 가짜 변경 → "없음" |
| 고치기 담당 | `%TEMP%` 사본에서 글자 한 줄 → 그 줄만 바뀜(다른 줄 0) | (같은 시험) |
| 배포 확인 | (지금 서버 상태) | 메인이 직접 돌린 명령 결과와 같음 |
| 문구 검토 | 사이트에 없는 사실을 지어낸 문구 → 잡음 | `index.html` 에 이미 있는 문구 → 통과 |

시험 2 동안 한국어 확인 훅에 막힌 명령이 있었는지 본다(가정 2).

**시험 3. 관리자 한 바퀴**(**새 대화에서** — 기다리기 설정이 새 대화부터)

- 가. "관리자에게 맡겨줘: 지금 사이트 상태 점검" — 일꾼 셋(시험 · 휴대폰 · 배포)이 동시에 도는지, 부른 이름이 이 설계의 일꾼뿐인지(가정 3),
  보고서가 여섯 칸인지, 숫자가 메인의 직접 확인과 같은지.
- 나. 메인이 기다리는지 — 자동 저장 메시지가 관리자 보고보다 먼저 뜨면 실패(가정 1).
- 다. "관리자에게 맡겨줘: `%TEMP%` 의 시험 파일 지워줘" — 지우지 않고 '여쭐 것'으로 돌려줘야 한다(잘못 지워도 버릴 파일).
- 라. 말로 부를 때만 — 화면 없이 띄운 클로드(`claude -p`, 훅 끄기, 쓰는 도구 막기)로 두 문장:
  "관리자에게 맡겨줘: 캐시 번호 점검" → 관리자가 불림 / "배포 확인해줘" → 관리자가 안 불림.

**시험 4. 실제 일 한 번**(사장님과) — 다음 실제 수정 하나를 관리자에게 맡겨 고치기 → 확인 → 보고 → 자동 저장 → 다음 차례 배포 확인까지.
써 보시고 불편한 점으로 지침을 고친다.

**성공 기준**: 시험 1~3 전부 통과. 하나라도 틀리면 그 도우미 지침을 고치고 그 시험만 다시.

**사용량(추정)**: 시험 2~3 에서 도우미를 열 번 남짓 부른다 — 평소 큰 작업 하나 정도.

## 하지 않는 것

- 관리자 전용 대화창(`claude --agent`, `settings.json` 의 `"agent"`) — 방법 ② 를 고르지 않음.
- 클로드가 알아서 관리자를 부르는 것 — 말로 부를 때만.
- 서류 데이터 세기 · 기록 정리 도우미 — 보류.
- 자동 저장 훅(`auto-save.sh`) 고치기 — 기다리기 설정으로 충분. 잠금(`%TEMP%\foodbell-save.lock`)은 10분이면 풀려 15분 시험에 맞지 않아 쓰지 않는다.
