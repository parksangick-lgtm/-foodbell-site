# 직원용 고정 링크 "오늘 일정" (`today.html`) — 설계서

- 날짜: 2026-10-21 · 사무실 PC · 사장님과 대화로 정함(설계 1부 · 2부 승인)
- 바탕: [일일 일정표 설계서](2026-10-19-daily-schedule-design.md). 같은 날 오전에 만든 `call.html`(전화 · 지도 링크)을 바꾸는 일이다.

## 왜 바꾸나 (10-21 첫 실제 사용)

오전에 만든 흐름: **직원에게 보내기** → 사진을 단톡방에 → 창이 또 뜸 → **[전화 · 지도 링크 보내기]** 로 링크를 한 번 더 →
직원이 링크를 누르면 줄 번호 · 번호 · 장소만 모은 화면(`call.html#…`, 번호가 링크 안에 들어 있음).

사장님이 써 보고 "엄청나게 불편하다"며 고른 세 가지:
1. **보낼 때 일이 두 번이다** — 사진 뒤에 링크를 매일 한 번 더 보내야 한다.
2. **직원이 쓰기 불편하다** — 링크 화면이 사진과 달라서 사진의 줄 번호와 맞춰 찾아야 한다.
3. **보낸 뒤에 고칠 수 없다** — 링크가 보낸 순간의 번호 · 장소를 담고 있어서, 일정표를 고쳐도 이미 보낸 링크는 옛날 것이다.

## 결정

| 항목 | 결정 |
| --- | --- |
| 방법 | **고정 링크 하나**를 단톡방 **공지**에 한 번 올린다. 링크는 열 때마다 저장소에서 **지금의** 일정표를 읽는다(사장님 선택 A — 매일 링크만 보내는 B 는 사진이 안 남아 신호가 약할 때 못 봐서 안 씀) |
| 매일 보내기 | 지금처럼 **사진만**. 사진 뒤에 뜨던 "전화 · 지도 링크" 창은 **없앤다** |
| 직원 화면 | 일정표마다 **오늘 · 내일 …** 버튼, 일마다 카드 한 장에 사진에 있는 내용 **전부**(금액 포함 — 사장님 10-21), 전화번호마다 **[전화]**, 장소에 **[지도]**(네이버 지도 검색, `call.html` 과 같은 방식). 줄 번호는 사진과 같다 |
| 로그인 | 없음 — 직원은 구글 계정이 없다(10-20 결정). 링크 속 **긴 암호**를 아는 사람만 읽는다 |
| 고친 뒤 | 일정표가 저장될 때마다 게시판에도 올라간다. 열려 있는 직원 화면은 새로고침 없이 바뀐다 |
| 링크 받기 · 바꾸기 | 일정표 화면에 버튼을 만들지 않는다. 클로드가 관리 도구로 만들어 대화창에 준다. 직원이 그만두면 "직원 링크 바꿔줘" — 새 암호, 옛 게시판 지움(옛 링크는 "링크가 바뀌었습니다") |
| 옛 `call.html` | 그대로 둔다(오전에 보낸 링크가 계속 열리게). 더는 만들지 않는다 |
| 공지 링크 | **직원 폰에서 확인함**(10-21 사장님 — 오픈채팅방 공지에 `https://foodbell.kr/` 를 올리고 직원 폰에서 공지를 눌러 열림) |

## 저장 자리와 보안 규칙

일정표 서류(`docs`)는 지금처럼 허락 목록(`allow`)의 사장님만 읽고 쓴다. 이와 따로 두 곳을 더한다.

| 자리 | 내용 | 읽기 | 쓰기 |
| --- | --- | --- | --- |
| `config/share` | `{ key: '<암호>' }` — 지금 쓰는 게시판 이름 | `allowed()` 만, 그 문서 하나(`get`) | 관리 도구(관리자 열쇠)만 |
| `share/{암호}` | 직원 게시판 한 장: `{ entries: { <일정표 문서 id>: 한 장 } }` | **누구나, 이름을 알면 그 문서 하나만**(`get: if true`). 목록 보기(`list`)는 규칙이 없어 거부 | `allowed()` 의 `update` 만 — 만들기 · 지우기는 관리 도구만 |

- 암호: 관리 도구가 `secrets.token_urlsafe(24)`(32글자)로 만든다 — 짐작해서 맞힐 수 없다.
  `share` 쓰기 규칙은 `entries` 칸만 바꾸게(`request.resource.data.keys().hasOnly(['entries'])`) 하고, 한 장에 일정표 40개까지(`entries.size() <= 40`).
- 이 규칙 파일은 공개 저장소에 올라간다 — 암호를 규칙 · 코드 · 문서에 적지 않는다.
- 링크는 `https://foodbell.kr/today.html#<암호>` — 암호는 `#` 뒤에만 있어 사이트 서버 · 카톡 미리보기 요청으로 가지 않는다.
- **알고 정한 위험:** 링크를 가진 사람은 누구나 오늘 · 앞으로의 일정(손님 연락처 · 장소 · 금액)을 본다. 사진을 넘기면 누구나 보는 것과 같지만, 고정 링크는 **앞으로의 일정도 계속** 보인다. 그래서 바꾸는 명령을 둔다.

### 게시판 한 장 (일정표 하나)

```
{ date: '2026-10-22', label: '2026년 10월 22일 (목)', lunar: '음력 9월 12일', order: '…', memo: '…',
  rows: [ { no: 1, staff, car, time, place, tel, work, amt, lead, leadTel, guideTel, hall, depart, cremate, memo } ],
  at: <서버 시각> }
```
- 칸 이름은 일정표의 `data-f` 를 따른다(`lead-tel` → `leadTel`, `guide-tel` → `guideTel`). 글자는 화면 글자 그대로(`clean`).
- `rows` 는 **채운 줄만**, `no` 는 일정표의 줄 번호(사진과 같은 번호 — 빈 줄을 건너도 번호는 그대로).
- `amt` 는 화면의 금액 글자. "단위를 적어 주세요" 알림은 넣지 않는다(사진 · 요약 글과 같음).
- 오늘 만든 칸(장례식장 · 발인 · 화장)이 없는 옛 일정표는 그 칸이 빈 글자로 들어간다.
- **날짜를 못 읽는 일정표는 올리지 않는다**(그 일정표의 칸을 게시판에서 뺀다). 새 일정표는 날짜가 미리 채워지므로 드문 경우다.

## 언제 올라가나 — 공통 부품(`js/docs/doc-page.js`) · 저장소(`js/sije/store.js`)

- 화면이 `window.FoodbellDoc.share()` 를 내주면(일일 일정표만) 공통 부품이 게시판에 올린다. 다른 서류 다섯 종은 내주지 않으므로 그대로다.
- 올리는 때: ① 일정표를 **처음 그렸을 때**(열기만 해도 — 처음 설치 뒤 바로 보이게) ② **저장할 때마다**(`flush` 가 `saveDoc` 을 부르는 자리) ③ 일정표를 **지울 때**는 그 칸을 뺀다.
- 주인(`owner`)만 올린다. 보기 전용(`viewer`)은 올리지 않는다.
- 저장소 쪽(`store.js`):
  - `config/share` 를 한 번 읽어 암호를 들고 있는다. 문서가 없으면(아직 안 만듦) 조용히 아무것도 안 한다.
  - `updateDoc(share/{암호}, { 'entries.<id>': {…, at: serverTimestamp()} , 'entries.<옛 id>': deleteField() … })` — **칸 하나씩** 고친다. 다른 기기가 다른 일정표 칸을 동시에 고쳐도 지워지지 않는다.
  - 같은 고침에서 **날짜가 어제보다 이전인 칸**을 지운다(처음 한 번 읽은 게시판을 보고). 어제 것은 남긴다 — 자정 무렵 폰 시계 차이.
- 실패해도 일정표 저장은 그대로다(따로 돈다). 실패하면 그 화면에서 **한 번만** 알린다: "직원 링크 화면에 올리지 못했습니다 (오류 이름)". 신호가 없을 때는 오류가 아니라 기기에 들고 있다가 연결되면 올라간다(저장소의 오프라인 저장).

## 직원 화면 `today.html`

- 새 파일. 저장소 읽기는 새 작은 부품 `js/sije/share-store.js` 만 부른다(로그인 부품을 받지 않아 약한 신호에서 가볍다). 연결 정보는 `firebase-config.js` 의 것을 같이 쓴다(127.0.0.1 · localhost 는 시험용).
- `#` 뒤 암호로 `share/{암호}` 를 지켜본다(`onSnapshot`) — 사장님이 고치면 저절로 바뀐다. 한 번 본 내용은 기기에 남겨 둔다(`persistentLocalCache`).
- 위에서부터:
  - 제목 `푸드벨 일정`(곱은바탕, `call.html` 과 같은 색 · 글꼴 — 글꼴은 기다리지 않는다 `media=print onload`).
  - 날짜 버튼: 날짜가 **오늘 이후**인 일정표만, 날짜 순. 오늘 = `오늘 10월 22일 (목)`, 내일 = `내일 10월 23일 (금)`, 그 뒤는 `10월 24일 (토)`. 같은 날짜가 둘이면 버튼도 둘. 처음 고른 것 = 오늘 것, 없으면 가장 가까운 날.
  - 고른 일정표: 큰 날짜 + 음력, 순번, 전달 메모(비면 숨김).
  - 일마다 카드: `1번` · 시간 · 담당 직원 · 차량 / 장소 **[지도]** / 연락처 번호마다 **[전화]** / 행사 내용 · 금액 / 팀장 · 팀장 전화 **[전화]** / 안내 **[전화]** / 장례식장 · 발인 · 화장 / 메모(줄바꿈 그대로). 빈 칸은 이름표까지 숨긴다.
  - [전화] = `tel:` + 숫자만(전화번호 모양만 — `call.html` 의 `telShape` 와 같다). 한 칸에 번호가 둘이면 버튼도 둘.
  - [지도] = `https://map.naver.com/p/search/` + 장소 글자(주소용으로 바꿔서).
- 이럴 때 글:
  - 암호가 없거나 게시판이 없다(바꾼 옛 링크): "링크가 바뀌었습니다. 단톡방 공지의 새 링크를 눌러 주세요."
  - 오늘 이후 일정이 없다: "올라온 일정이 없습니다. 단톡방의 일정표 사진을 확인해 주세요."
  - 기기에 남은 것만 보인다(연결 안 됨): 위에 작게 "연결 안 됨 — 마지막으로 받은 내용입니다".
- `<title>푸드벨 일정</title>`(카톡 미리보기 카드 제목), `noindex`.
- 오프라인 사본: `sw.js` 의 `OFFLINE_PAGES` 에 `today.html` 을 넣고 `CACHE` 를 올린다. 카톡 안 화면에서도 되는지는 확인 못 함 — 안 되면 사진이 대비책.

## 일정표 화면(`daily-schedule.html`)에서 바뀌는 것

- 뺀다: `#call-dlg` 창, `callLink` · `offerCallLink` · `CALL_KIND`, 보내기 뒤 창을 띄우던 두 곳(휴대폰 공유 뒤 · PC 복사 뒤).
- 남긴다: 전화번호 작대기 넣기(`telShape` · `dashTels`), 사진 보내기 · 복사 · 인쇄 · 파일로 저장은 그대로.
- 더한다: `window.FoodbellDoc.share()` — 위 "게시판 한 장"을 화면 칸에서 만든다(`buildText` 가 칸을 읽는 방식과 같다).
- `call.html` 머리 주석의 "만드는 쪽은 callLink" 를 "더는 만들지 않음 — 10-21 오전에 보낸 링크용" 으로 고친다.

## 관리 도구 `tools/sije_web/share_link.py`

```
python -m tools.sije_web.share_link show --key C:\foodbell-keys\sije-admin.json   # 지금 링크 보기
python -m tools.sije_web.share_link new  --key C:\foodbell-keys\sije-admin.json   # 새 암호(처음 만들기 · 바꾸기)
```
- `new`: 새 암호 → `share/<새 암호>` 를 만들고(`entries` 는 옛 게시판 것을 옮김 — 바꾼 직후에도 일정이 보이게) → `config/share` 를 새 암호로 → 옛 `share/<옛 암호>` 를 지운다 → 새 링크를 찍는다.
- 바꾼 순간 열려 있던 사장님 일정표 화면은 옛 암호를 들고 있어 올리기가 실패한다("올리지 못했습니다" 한 번) — 화면을 다시 열면 새 게시판에 올린다.
- `show`: 링크를 찍는다(없으면 "아직 없음 — new 로 만드세요").
- 시험용은 `--key C:\foodbell-keys\sije-test-admin.json`.

## 순서 — 규칙을 실제 저장소에 먼저

자동 저장이 답이 끝날 때마다 사이트에 올린다. 게시판에 올리는 코드가 규칙보다 먼저 게시되면, 사장님 화면에 "직원 링크 화면에 올리지 못했습니다" 가 뜬다. 그래서:
1. 규칙 · 관리 도구 · 규칙 시험을 **시험용 저장소**에서 끝낸다.
2. **사장님께 묻고** 실제 저장소에 규칙을 올리고 실제 게시판을 만든다(되돌리기 어려운 바깥 작업 — 직전에 묻는다).
3. 그다음 화면 코드(`store.js` · `doc-page.js` · `share-store.js` · `today.html` · `daily-schedule.html` · `sw.js`)를 끝낸다.

## 성공 기준과 확인

1. 자동 시험(시험용 저장소, 가짜 자료 — `가짜동` · `010-0000-0000` 꼴):
   - 규칙: 로그인 안 한 사람이 암호로 게시판 **읽기 됨** + 같은 사람이 **쓰기 막힘** · **목록 막힘** · `config/share` **막힘**; 주인은 게시판 쓰기 · `config/share` 읽기 **됨**(막힘은 같은 사람의 됨과 함께 본다).
   - 관리 도구: `new` 두 번 → 옛 게시판이 없어지고 칸은 새 게시판으로 옮겨짐, `show` 가 새 링크.
   - 일정표를 고치면 → 열려 있는 직원 화면(로그인 없는 다른 창)이 새로고침 없이 바뀐다.
   - 직원 카드: 줄 번호(빈 줄을 건너도 사진 번호) · 칸 글자 · `tel:` 주소 · 네이버 지도 주소 · 번호 둘이면 버튼 둘 · 금액 · "단위를 적어 주세요" 가 안 나옴.
   - 날짜 버튼: 오늘 · 내일 표시, 어제 일정은 안 보임, 지운 일정표는 사라짐, 날짜를 못 읽는 일정표는 안 올라감.
   - 잘못된 암호 → "링크가 바뀌었습니다", 일정 없음 → "올라온 일정이 없습니다".
   - 보내기(휴대폰 공유 · PC 복사) 뒤 두 번째 창이 안 뜬다.
   - 지금 있는 시험이 전부 통과한다(옛 `call` 창 시험은 지우고, `call.html` 이 옛 링크를 여는 시험은 남긴다).
2. 휴대폰 폭 390px 에서 `today.html` 을 사진으로 찍어 넘침 · 잘림이 없는지(`clientWidth` 되읽기).
3. 자동 저장으로 올라간 뒤 `https://foodbell.kr/today.html` 이 `200`.
4. 사장님 확인: 공지에 새 링크 → 직원 폰에서 [전화] · [지도] · 일정표를 고친 뒤 링크 화면이 바뀌는지.

## 하지 않는 것

- 직원 로그인 · 직원 이름별 보기 · 알림(푸시) · 일정표 화면의 "직원 링크" 버튼 · 직원이 고치기.
- 사진을 링크 화면에 넣기(화면이 사진을 대신한다).
- 옛 `call.html` 지우기.
