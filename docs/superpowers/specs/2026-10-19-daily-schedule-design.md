# 직원용 일일 일정표 서류 설계 (2026-10-19)

사장님과 대화로 정한 것(사무실 PC 18:30 에 1차 결정 → 노트북 같은 날 저녁에 나머지 결정).
이 문서가 확인되면 작업 계획 → 만들기로 넘어간다.

## 목적

사장님이 **매일 저녁 그날그날(다음 날) 일정을 직접 채워** 직원 카톡 단톡방에 **사진으로** 올리는 서류.
직원에게 시제행사 내역서는 공유하지 않는다 — 이 서류가 직원에게 가는 유일한 일정이다.
서류 웹(`js/docs/`)의 여섯 번째 서류로, 견적서 · 거래명세서 · 알바비처럼 로그인 · 목록 · 저절로 저장 · 지우기를 그대로 쓴다.

## 사장님이 정한 것

| 항목 | 결정 |
| --- | --- |
| 올리는 곳 | 카톡 단톡방에 사진으로 — "직원에게 보내기" → 사진 → 카톡 (견적서 · 알바비와 같은 방식) |
| 서식 | 서류 웹에 새 서류 하나 (로그인 · 목록 · 저절로 저장) |
| 이름 | **일일 일정표** (목록 제목 · 아이콘 이름) |
| 칸 | 맨 위 날짜 · 요일 크게 / 한 줄(일 하나)마다 시간 · 장소 · 행사 내용 / 담당 직원 · 차량 / 집합(출발) 시간 · 장소 / 메모 — **10-20 에 바뀜, 아래 "종이 모양" 표가 최신** |
| 채우는 법 | **전부 직접** — 시제행사 목록에서 불러오기 없음 |
| 새로 만들 때 날짜 | **내일 날짜 · 요일**로 미리 채움 (고칠 수 있음) |
| 전달 메모 | 표 위에 한 칸 둔다 (그날 전체 공지). 비어 있으면 보기 · 사진 · 인쇄에서 숨김 |
| 아이콘 바탕색 | **주홍** |
| 직원용 캘린더 | "푸드벨 일정(직원용)"(10-19 만든 것)은 **그대로 둔다** — 아무에게도 공유하지 않음 |

클로드가 제안해 사장님이 설계 승인으로 받아들인 것: 요일은 날짜를 보고 **저절로 계산**한다(날짜만 고치고 요일을 깜빡하는 실수 막기).

### 10-20 추가 결정 — 밴드에 올려 온 실제 일정을 보고 (집 PC)

밴드 "박상익출장음식"의 지난 일정 글 33개(9-16~10-20)를 읽었다. 저녁 6~9시에 **다음 날** 일정을 올리고, 글은
`날짜` + `1.직원.직원 6시30분출발` 줄(하루 1~15건), 자세한 것은 수첩 사진 한 장(맨 위 순번 · 일마다 장소 · 행사 · 시간 ·
연락처 · 인원×단가=금액 · 오른쪽 여백에 담당). 가끔 맨 위에 고정 전화 규칙("납골당은 출발 전 전화 …"), "연기" 표시가 있다.
(실제 이름 · 연락처는 이 문서와 시험 자료에 옮기지 않는다.)

| 항목 | 결정 |
| --- | --- |
| **순번** | 날짜 아래 한 줄 "순번: ○○ · ○○ · ○○". 일을 맡는 차례지만 **배정은 사장님이 상황에 맞춰 직접** — 자동 배정 없음. 한 직원이 두 군데를 맡기도 한다(담당 칸은 자유 글자). 순번 줄을 둔 것은 클로드 가정 — 빼라고 하면 뺀다 |
| **연락처** | 일마다 상주 · 담당자 전화. 사진이 단톡방 모두에게 보인다는 것을 알고 넣음 |
| **인원 · 단가 · 금액** | 일마다 인원 × 단가, 금액은 저절로 계산(`60명 × 15,000원 = 900,000원`). 10-19 의 "시제 내역서는 공유하지 않는다"와 별개로 일정표에는 금액도 적는다(사장님 선택) |
| **이어받기** | "새 일정표"를 누르면 **가장 최근에 고친 일정표**의 순번 줄 · 전달 메모를 그대로 가져온다(필요 없으면 지운다). 날짜는 여전히 내일 |
| **첫 전달 메모** | 이어받을 일정표가 하나도 없을 때(맨 처음)는 이 글로 채운다: "추모공원(협력업체)은 회사에서 출발 전에 전화 · 화장은 시작 5분 후 전화 · 매장은 발인 5분 전에 팀장에게 전화 · 상주(직접주문)에게는 가게 출발 전에 전화" |
| **사이트 주소** | 표제의 "푸드벨" 옆에 `foodbell.kr` — 누르면 `https://foodbell.kr/` 가 열린다(화면에서). 사진으로 보낸 일정표에서는 글자로만 보이고 눌리지 않는다. 복사(문자용 요약)에는 맨 끝에 `https://foodbell.kr/` 를 한 줄로 넣어 카톡에서 눌리게 한다(브랜드 가이드: 주소는 줄 하나에 혼자) |

### 10-20 추가 결정 2 — 밴드 대신 쓴다 (집 PC)

| 항목 | 결정 |
| --- | --- |
| **음력** | 큰 날짜 옆에 작게 `음력 9월 11일`(윤달은 `음력 윤6월 1일`). 날짜를 보고 저절로 계산 — 브라우저의 한국 음력(`Intl` `ko-KR-u-ca-dangi`). 10-20 에 2024~2035년 4,383일을 한국천문연구원 기준 계산(`korean_lunar_calendar`)과 맞대어 Node · 크로미움 모두 틀림 0, 윤달 116일 맞음. 중국식(`chinese`)은 하루 어긋나는 날이 있어 **대신 쓰지 않는다** — 단기력을 모르는 브라우저면 음력을 비운다. 날짜를 못 읽어도 비운다. 복사 글 · 옵시디언 사본의 날짜 줄에도 붙인다 |
| **문자 붙여넣기** | 주문이 문자로 온다. 일정표(편집 중)의 줄마다 "문자 붙여넣기" — 문자 전체를 한 번에 붙여넣으면 **모양이 분명한 것만** 칸에 나눠 넣고(전화번호 → 연락처, 시각 → 시간, `○○명` → 인원, `○○원`/`○만` → 단가 — 정확한 규칙은 **실제 주문 문자 표본**으로 정한다 → 아래 '10-20 추가 결정 3' 으로 바뀜: 인원은 안 뽑음, 메모는 원문 전체), 나머지는 메모에 원문 그대로. 이미 적힌 칸은 덮지 않는다. AI 로 읽기는 하지 않는다(사용료 · 손님 정보 외부 전송). **일정표에만** — 시제행사 목록에는 넣지 않는다 |
| **QR** | 이미 있는 `design/qr/qr-화면.png`(foodbell.kr, 오류정정 M)를 표제 오른쪽(인장 옆)에 작게. 사진으로 받은 폰에서는 못 찍으니 주로 인쇄용 |
| **직원은 보기만** | 직원(10명, 모두 갤럭시 — 구글 계정 있음)이 자기 구글 계정으로 로그인. 다른 로그인 방법은 만들지 않는다. 사장님이 알려 준 메일만 **보기 명단**(`viewers`)에 넣는다. 직원에게는 **일정표만** 보이고(다른 서류 목록 · 화면은 권한 없음), 편집 · 지우기 · 새 일정표 버튼이 없다. 보내기 · 복사 · 인쇄 · 파일로 저장은 된다. 그만두면 명단에서 뺀다 |
| **A4 한 장** | 인쇄는 A4 세로 한 장 기준. 넘치면 다음 장으로 넘어가고 표 제목 줄이 다시 나온다(줄 하나가 두 장에 갈라지지 않게). **카톡 사진도 장마다** 나눠 `1/2`, `2/2` 로 보낸다(파일 이름 `일일일정표_YYYY-MM-DD_1.png` …) |
| **저장** | 서류 웹(파이어베이스)에 저절로 저장 + 사무실 PC 매일 엑셀 백업 — 그대로. 밴드처럼 지난 일정은 목록에서 본다 |
| **알림** | **카톡**으로 — 다 쓰고 "직원에게 보내기"를 누르면 단톡방에 사진(장마다)이 올라가 직원은 카톡 알림을 받는다. 공유 글에 일정표 주소 `https://foodbell.kr/daily-schedule.html` 한 줄을 붙인다(카톡이 사진과 글을 함께 받지 않는 기기에서는 글이 빠질 수 있음 — 사진이 주인). 저장할 때마다 알리지 않는다. 휴대폰 앱 알림(푸시)은 만들지 않는다 — 써 보고 필요하면 따로 |
| **옵시디언 사본** | 사장님 개인 기록용(직원은 못 봄). 사무실 PC 상주 프로그램(`office_agent.py`)이 일정표가 새로 생기거나 바뀌면 볼트의 `푸드벨-업무/일일 일정표/2026-10-21 (수).md` 에 복사 글과 같은 내용을 쓴다(바뀌면 덮어씀, 지운 일정표의 노트는 남김). 볼트 경로는 `obsidian-save` 와 같은 방식으로 찾고, 못 찾으면 건너뛰고 기록만 남긴다 |

보기 명단을 위한 보안 규칙(자세한 것은 작업 계획에서):
- `viewers/{메일}` 묶음 — `allow` 처럼 관리자 열쇠로만 고친다(`tools/sije_web/allow.py` 에 보기 명단 명령 추가).
- `docs` 읽기 = `allowed()` **또는** (`viewer()` 이고 그 서류의 `kind == 'daily-schedule'`). 쓰기 · 지우기는 `allowed()` 만.
- 화면이 "나는 보기 전용인가"를 알 수 있게, 로그인한 사람은 **자기 메일의** `allow` · `viewers` 문서만 읽을 수 있게 한다(남의 것은 여전히 못 읽음).

### 10-20 추가 결정 3 — 실제 카톡 주문 9개를 보고 (노트북)

사장님이 카톡 주문 9개(상조 · 공원 · 장례식장)를 캡처로 보내 줌. 표본은 이름 · 번호 · 거래처를 가짜로 바꿔
`tools/sije_web/js-tests/fixtures/order-samples.json` 에 둔다. 위 "문자 붙여넣기" 줄의 규칙을 이것으로 바꾼다.

| 칸 | 결정 |
|---|---|
| **시간** | 상차림 · 도착 시간만 — `도착` 이 그 줄(또는 바로 앞 줄)에 있는 시각, 없으면 `일시` 줄, 없으면 화장 · 발인 · 회차가 아닌 첫 시각. 화장 · 발인 시간만 있으면 비운다. 적힌 그대로(`3시`, `11시20분`) — 오전 · 오후를 짐작하지 않는다 |
| **연락처** | 휴대폰 번호(010 …, 하이픈 없어도 `010-0000-0000` 꼴로). 계좌 · 묘역번호 · 번지 · 끝이 모자란 번호는 안 뽑는다 |
| **인원** | **뽑지 않는다** — 상 주문은 인원이 없고, `식사100인분` × `평토상 35만` 처럼 곱하면 틀린 금액이 된다 |
| **단가** | `35만(원)` · `15,000원` 같은 값이 하나일 때만 |
| **메모** | 원문 그대로 다(뽑은 것도 지우지 않음, 줄바꿈도 그대로) — 긴 글은 사진에서 줄이 길어지니 필요 없는 줄은 사장님이 지운다 |
| **금액 표시** | 인원 · 단가 둘 다 있으면 곱셈, **단가만 있으면 단가만**(`350,000원`) 보인다 — 인원이 애매(`60~70명`)해도 단가만. (위 "둘 중 하나 비우면 숨김" 을 바꿈: 단가가 비면 숨김) |

## 종이 모양 (사진으로 나가는 부분)

본보기는 알바비 지급내역서(`staff-pay.html`) — 스타일 · 편집 · 저장 · 보내기 틀을 그대로 빌린다(`table.stmt` 클래스).

1. **머리**: 다른 서류와 같은 표제(푸드벨 · 소개 한 줄 · 전화번호 · 인장), 오른쪽 제목 "일일 일정표".
   문서번호 · 작성일자 칸은 두지 않는다(직원에게 필요 없음 — 목록에 고친 시각이 보인다).
2. **큰 날짜 줄**: `2026년 10월 20일 (화)` — 명조 굵게, 서류에서 가장 큰 글자.
   - 날짜 부분(`2026년 10월 20일`)만 고칠 수 있다. 요일 `(화)` 는 화면이 계산해 붙인다.
   - 날짜를 못 읽으면(연 · 월 · 일 숫자 셋이 없음, 또는 2월 30일처럼 없는 날) 요일을 비운다.
3. **순번** 한 줄 — `순번:` 뒤에 자유 글자. 비면 숨김. 새 일정표는 최근 일정표 것을 이어받는다.
4. **전달 메모** 한 줄 — 알바비의 `.memo` 그대로. 비면 숨김. 새 일정표는 최근 일정표 것을 이어받는다.
5. **표** — 한 줄 = 일 하나. 칸은 여섯 그대로 두고 연락처 · 인원 · 금액은 두 칸 아래에 붙인다(8칸이면 A4 · 휴대폰에서 너무 빽빽함):

   | 칸 | 들어가는 것 | 모양 |
   | --- | --- | --- |
   | 번호 | 1, 2, 3… (저절로) | |
   | 시간 · 장소 · 연락처 | 시간(위, 굵게) + 장소 + 연락처(아래) | 세 줄 칸 |
   | 행사 내용 · 인원 · 금액 | 행사 내용(위) + `인원 명 × 단가 원 = 금액`(아래, 금액은 저절로) | 두 줄 칸 — 인원 · 단가가 비면 아래 줄 숨김 |
   | 담당 직원 · 차량 | 담당 직원(위) + 차량(아래) | 두 줄 칸 |
   | 상조팀장 · 현지 안내인 | 상조팀장 이름(위, 굵게) + 팀장 전화 + `안내` 현지 안내인 전화(아래) | 세 줄 칸 — 비면 휴대폰 보기에서 숨김 |
   | 메모 | 예: 연기 | 비면 휴대폰 보기에서 숨김 |

   (10-20 견본을 보고 사장님이 **집합 시간 · 장소 칸을 빼고** 상조팀장 · 현지 안내인 칸으로 바꿈. 출발 시각이 필요하면 담당 칸이나 메모에 적는다.)
   **칸 순서는 10-20 에 다시 정함: 번호 → 담당 직원 · 차량 → 시간 · 장소 · 연락처 → 행사 내용 · 인원 · 금액 → 상조팀장 · 현지 안내인 → 메모**
   (위 표의 줄 순서보다 이 줄이 최신). 휴대폰 카드도 번호 옆 첫 줄이 담당 직원.

   편집할 때 두 줄 칸도 한 칸씩 따로 누르고, 빈 칸에는 무엇을 적을지 흐린 글자로 보인다(알바비의 `data-ph`).
   줄 추가(`＋ 줄 추가 (일 하나)`) · 줄 삭제는 알바비와 같다.
6. **합계 칸 없음** — 일마다 금액은 있지만 하루 합계는 부탁받지 않았다(필요하면 따로).

휴대폰(620px 이하)에서는 표가 줄마다 카드: 번호 · 담당 · 차량 / 시간 · 장소 · 연락처 / 행사 내용 · 인원 · 금액 / 상조팀장 · 현지 안내인 / 메모 순.
인쇄는 A4 한 장(알바비와 같은 인쇄 규칙).

## 버튼 · 보내기

알바비와 같은 6개: 편집 / 파일로 저장 / **직원에게 보내기** / 복사 / 인쇄 · PDF / 목록.

- **직원에게 보내기**: 휴대폰은 공유창(카톡 단톡방 고르기), PC 는 사진을 클립보드에 넣고 다운로드 폴더에도 저장 → 카톡 대화창에서 Ctrl+V.
  공유 제목 `푸드벨 일일 일정표 (2026년 10월 20일 (화))`.
- 채운 일이 하나도 없으면 "일정을 아직 안 넣으셨습니다. 그래도 보낼까요?" 를 묻는다(파일로 저장도 같음).
- **복사**(문자용 요약): 제목 · 날짜(요일) · 순번 · 전달 메모 · 일마다 한 덩어리(번호. 시간 장소 연락처 — 행사 내용 인원×단가=금액 / 담당 · 차량 / 상조팀장 이름 전화 · 안내 전화 / 메모). 빈 칸은 뺀다.
- 위 안내문(`.hint`)은 알바비 문장을 이 서류에 맞게 바꾼다. "사진은 단톡방 모두가 봅니다" 한 마디를 넣는다
  (알바비 안내의 "받는 사람을 꼭 확인하세요" 와 같은 취지).

## 저장 · 목록 (공통 부품에 붙이기)

- 연결 고리 `window.FoodbellDoc` — `kind: "daily-schedule"`, `serialize` · `load` · `fresh` · `summary` · `editing` (알바비와 같은 모양).
- `fresh()` = 빈 서식 + 날짜를 **내일**로 + 요일 계산.
- 이어받기: 공통 부품 `makeNew` 가 `D.fresh()` 다음에, 서류에 `inherit` 가 있으면 목록에서 **가장 최근에 고친 같은 종류 서류**
  (목록이 받아 둔 `rows` 를 `sortDocs` 한 첫 줄의 `.doc` — 저장된 `html` 이 들어 있다)를 넘겨 `D.inherit(doc)` 를 부른다 — 일정표는 그 서류의 저장된 화면에서 순번 · 전달 메모만 꺼내 채운다.
  다른 서류에는 `inherit` 가 없으니 그대로다. 목록이 비었거나 꺼낼 칸이 없으면 빈 채로 둔다.
- `summary()` = `{ label: "2026년 10월 20일 (화)", issue: 같은 글자, total: "", count: "3건" }` — 무엇이든 하나라도 적힌 줄을 센다.
- 목록 한 줄(`rowCells`): `[날짜(요일) 또는 "(날짜 없음)", "N건"(없으면 "0건"), ""]` + 고친 시각.
  순서는 다른 서류처럼 최근에 고친 것이 위(`sortDocs` 그대로).
- 백업 엑셀(`backup.py`)의 "서류" 시트에 종류 이름 "일일 일정표" 로 들어간다. "인원" 칸에 "3건" 이 들어가는 것은 그대로 둔다(칸 이름만 어긋남, 글자가 스스로 설명함).

## 올리는 차례 (실제 서버)

1. 보안 규칙을 **시험 프로젝트**에 올리고(`--project test`) 시험을 돌린다.
2. 보안 규칙을 **실제 프로젝트**에 올린다(`--project default`) — **올리기 직전에 사장님께 다시 묻는다.**
   이 문서에 적힌 승인은 그 순간의 승인이 아니다.
3. 그다음 화면 파일을 GitHub(`office`)에 올린다 → 버셀이 foodbell.kr 에 게시.
   규칙보다 화면이 먼저 올라가면 "새 일정표" 가 권한 없음으로 실패하므로 이 차례를 지킨다.
4. 사무실 PC 백업 프로그램은 상주 프로그램이라, 예약 작업 "푸드벨 시제 PDF" 를 껐다 켜야 백업에 "일일 일정표" 이름이 붙는다.
   안 켜도 고장은 없다(종류 칸에 `daily-schedule` 영문이 들어갈 뿐) — 사장님이 사무실 PC 에 있을 때 한다.

## 성공 기준 · 확인 방법

- 자바스크립트 시험(`node --test`)과 파이썬 시험(`pytest`, 일정표 관련 + 기존 서류 시험)이 모두 통과한다.
- `python 휴대폰캡처.py` 의 390px 캡처에서 일정표가 넘치지 않는다(되읽은 폭 390, 넘침 0).
- 시험 프로젝트에서: 새 일정표 → 날짜가 내일 · 요일이 맞음 → 날짜를 고치면 요일이 따라 바뀜 → 칸 채우기 →
  저절로 저장 → 목록에 "날짜(요일) · N건" 으로 보임 → 다른 창(휴대폰 폭)에서 같은 일정표가 보임.
- 실제 게시 후 `curl` 로 `https://foodbell.kr/daily-schedule.html` 이 200.
- 사장님 휴대폰에서 실제로 단톡방에 사진 보내기 — 사장님 몫(결과를 들으면 기록).
