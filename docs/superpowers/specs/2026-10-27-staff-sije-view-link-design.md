# 담당자용 시제 내역서 보기 링크 (`sije-view.html`) — 설계서

- 날짜: 2026-10-27 · 사무실 PC · 사장님과 대화로 정함
- 바탕: [직원용 고정 링크 설계서](2026-10-21-staff-today-link-design.md)(로그인 없는 직원 화면 · 링크 속 암호),
  같은 날 만든 `확정 (인쇄 전)` 흐름(`tools/sije_web/pdf_sync.py` · `printed.py`), 직원용 캘린더(`calendar_sync.py`, 10-19)

## 왜 만드나

지금은 행사 나가는 직원에게 내역서를 **A4 로 복사해** 준다. 관리가 안 되고 종이가 상한다.
보관용 인쇄는 사장님이 따로 한다(`확정 (인쇄 전)` → 인쇄 → 합치기). 그래서 직원에게 줄 것은 **휴대폰으로 보는 내역서**다.

## 결정

| 항목 | 결정 |
| --- | --- |
| 누가 보나 | **그 행사 담당자만 — 행사마다 링크 하나**(사장님 10-27). "고른 몇 명에게 링크 하나"는 고르지 않음. 단톡방 공지의 '푸드벨 일정'(`today.html`)에는 **넣지 않는다** — 직원 모두가 보므로 |
| 고치기 | **못 한다 — 보기만**(사장님 10-27) |
| 보이는 기간 | **행사 전날과 당일**(오늘 · 내일 날짜의 내역서). 행사 다음 날 사라진다. 그 밖의 때에 열면 안내 글 |
| 보이는 것 | 날짜 · 시간, 장소, 상차림, 시제일, 산신제, 식사, 담당 · 차량, 출발 · 도착 시간, **손님 · 연락처**([전화]), **금액 · 금액 내역**, 꼭 지킬 것, 준비 품목(구분 · 품목 · 수량 · 비고), 추가 기입, 메모(사장님 10-27 — 금액도 넣음) |
| 안 보이는 것 | 붙인 그림(신호 약한 산에서 느림 — 사장님 10-27 빼기로), 미확정용 칸(예상 날짜 · 근거 · 확인 글), 파일 이름 · 원본 칸, 상태, 인쇄 표시, 수량과 비고가 **둘 다 빈** 품목 줄 |
| 어떤 행사 | **확정만.** 미확정 · 주문없음이 되면 담당자 화면에서도 사라진다 |
| 고친 뒤 | 사무실 PC 프로그램이 5분마다 올린다 → 사장님이 고치면 **5분 안에** 담당자 화면이 바뀐다(열려 있으면 새로고침 없이). 사무실 PC 가 꺼져 있으면 마지막으로 올린 것이 보인다 |
| 링크 보내기 | 내역서 화면 단추줄에 **[담당자 링크]**. 휴대폰은 글만 담은 공유창(카톡에서 담당자를 고름), PC 는 클립보드에 복사. 행사마다 링크 하나 — 처음 누를 때 만들고, 다시 누르면 같은 링크 |
| 링크 모양 | `https://foodbell.kr/sije-view.html#<암호>` — 암호는 `#` 뒤에만 있어 서버 · 카톡 미리보기 요청으로 가지 않는다 |
| 신호 약할 때 | 한 번 연 내역서는 휴대폰에 남아서 보인다(`today.html` 과 같은 방식) |

## 저장 자리와 보안 규칙

| 자리 | 내용 | 읽기 | 쓰기 |
| --- | --- | --- | --- |
| `events/{id}.viewKey` | 그 행사의 보기 암호(브라우저 `crypto.getRandomValues` 24바이트 → base64url 32글자) | `allowed()` (지금 규칙 그대로) | 사장님 화면 — **고친 시각(`updatedAt`)은 바꾸지 않는다**. 바꾸면 PDF 를 다시 그리고 인쇄한 확정이 `확정 (인쇄 전)` 으로 간다 |
| `staffSheets/{암호}` | 담당자 보기 한 장(아래) | **누구나, 이름을 알면 그 문서 하나만**(`get: if true`). 목록 보기(`list`) 규칙 없음 → 거부 | 관리자 열쇠(사무실 PC 프로그램)만. 화면 쓰기 규칙 없음 |

규칙에 더하는 것:

```
match /staffSheets/{key} {
  allow get: if true;
}
```

- `events` 쓰기 규칙은 이미 `allowed()` 면 아무 칸이나 고칠 수 있다(상태 값만 검사) — `viewKey` 때문에 바꿀 것 없음.
- 이 규칙 파일은 공개 저장소에 올라간다 — 암호를 규칙 · 코드 · 문서에 적지 않는다.
- **알고 정한 위험:** 링크를 넘겨받은 사람은 그 행사 내역서(손님 연락처 · 금액 포함)를 전날 · 당일에 본다. 행사 다음 날 사라진다.
  링크를 바꾸는 단추는 만들지 않는다(행사가 끝나면 저절로 닫히므로).

### 담당자 보기 한 장 (`staffSheets/{암호}`)

```
{ date: '2026-10-31', time, place, titlePlace, setting, templateType, sijeil, sansinje, meal, staffCar,
  departTime, arriveTime, customer, contacts: ['010-…', …], amount, amountDetail, mustDo, extraItems, memo,
  items: [ { group, name, qty, note }, … ],   // 왼쪽 L01… 다음 오른쪽 R01… (내역서 표 순서), 수량 · 비고 둘 다 빈 줄 뺌
  at: <서버 시각> }
```

- 칸 이름은 내역서(`events`)와 같다. 실제 확정 65건이 모두 이 칸들을 가지고 있음을 확인했다(10-27, 칸 이름 · 건수만 셈).
- 하루 최대 8건(11월) — 한 장씩 따로라 크기 걱정 없음.

## 사무실 PC 프로그램 — `tools/sije_web/staff_sheets.py` (새 파일), `office_agent.one_cycle` 에 한 단계

- `staff_view(ev) -> dict` — 위 한 장을 만든다(순수 함수, 시험 쉬움).
- `sync_staff_sheets(db, today) -> {written, removed}` — 차례마다:
  1. `events` 에서 `date in [오늘, 내일]`(PC 시계 = 한국 시각) 을 읽는다.
  2. `status == '확정'` 이고 `viewKey` 가 있는 것만 한 장을 만든다. 지금 올라가 있는 한 장과 **다를 때만** 쓴다(`at` 은 비교에서 뺌) — 담당자 휴대폰이 쓸데없이 다시 받지 않게.
  3. `staffSheets` 전체를 읽어, 이번에 고른 암호에 없는 것은 지운다(지난 행사 · 확정 풀림 · 날짜 바뀜).
- `one_cycle` 에서 PDF · 백업 · 캘린더 · 옵시디언과 **따로 감싼다** — 하나가 실패해도 나머지는 돈다. 기록: "담당자 내역서 올림: 2026-10-31" · "담당자 내역서 지움: …"(장소 · 손님은 기록에 안 씀 — 날짜만).
- 링크를 처음 만든 직후(`viewKey` 만 생기고 `updatedAt` 은 그대로)도 다음 차례에 올라간다 — 이 단계는 `updatedAt` 이 아니라 날짜로 고르기 때문.
- **코드를 바꾼 뒤 예약 작업 "푸드벨 시제 PDF" 를 껐다 켜고, 켜진 시각이 코드 바꾼 시각보다 나중인지 본다**(파일을 바꿔도 돌고 있는 프로그램은 안 바뀐다).

## 담당자 화면 — `sije-view.html` (새 파일)

- `today.html` 처럼: 로그인 없음, `noindex`, 휴대폰 먼저(390px), 브랜드 색 · 글꼴은 `today.html` 과 같게.
- `#` 뒤 암호로 `staffSheets/{암호}` 를 실시간으로 읽는다 — `js/sije/share-store.js` 에 `watchSheet(key, cb, onError)` 를 더한다(`watchShare` 와 같은 방식, 기기 저장 포함).
- 한 장이 없으면: "지금은 볼 수 없는 내역서예요. 행사 전날부터 당일까지 열려요. 링크가 맞는지 사장님께 여쭤 주세요."
- 보이는 차례: 머리(날짜 · 시간 · 장소 · 상차림) → 손님 · 연락처([전화] `tel:`) → 금액 · 금액 내역 → 담당 · 차량 · 출발 · 도착 · 산신제 · 식사 · 시제일 → **꼭 지킬 것** → **준비 품목**(구분마다 한 묶음: "배 5개 · 사과 5개 …", 비고는 괄호) → 추가 기입 → 메모. 빈 칸은 줄째 숨긴다.
- 장소에 [지도] — `today.html` 과 같은 네이버 휴대폰 검색 주소.
- 인쇄 · 사진 · 고치기 단추 없음.

### 휴대폰에서 잘리지 않게 (사장님 10-27)

- **표를 쓰지 않는다.** 엑셀 모양 내역서 표(13칸)는 휴대폰 폭에 안 들어가므로, 위에서 아래로 쌓는 줄 · 묶음으로 그린다.
  준비 품목은 구분마다 한 묶음, 품목은 "배 5개" 처럼 글로 이어 쓰고 폭이 모자라면 다음 줄로 넘어간다.
- **가로로 밀리는 것이 없다.** 고정 폭 · 최소 폭을 주지 않고, 긴 글(긴 장소 · 긴 꼭 지킬 것 · 긴 비고 · 이어진 숫자)은 줄을 바꾼다
  (`overflow-wrap: anywhere`, 한글은 낱말 단위 `word-break: keep-all`). 화면 전체에 가로 스크롤이 생기지 않는다.
- 글자는 14px 이상, 누르는 자리([전화] · [지도])는 44px 이상(사이트 규칙).
- 확인하는 폭: **360px**(작은 갤럭시) · **390px** — 둘 다 오른쪽 끝을 넘는 요소 0개(`휴대폰캡처.py` 와 같은 방식으로 요소마다 잼).
  휴대폰 글자를 크게 해 둔 직원도 있으니 **글자 1.3배**로도 같은 확인을 한다.
- 일부러 긴 가짜 자료로 시험한다: 장소 60글자, 꼭 지킬 것 5줄, 연락처 5개, 비고 40글자, 품목 30줄.
- 카톡 안에서 링크를 누르면 카톡 브라우저로 열린다 — 시험은 안드로이드 카톡 브라우저 이름표(user agent)로도 연다(기록장 #35).
- `sw.js`: `OFFLINE_PAGES` 에 더하고 `CACHE` 를 올린다.

## 내역서 화면 — `sije-sheet.html` · `js/sije/sheet-page.js` · `js/sije/store.js`

- 단추줄(그림 붙이기 · 인쇄 · 목록 옆)에 **[담당자 링크]** — 인쇄 · PDF 에는 안 나온다(`no-print`).
- 누르면:
  1. `viewKey` 가 없으면 만들어 저장한다 — 새 `store.setViewKey(id, key)` 는 `updateDoc(ref, { viewKey })` 만(고친 시각 안 바꿈).
  2. 보낼 글: `[푸드벨] 10월 31일 (토) 10시 ○○ 시제 내역서 (보기만)` 줄 + 링크 줄 + `행사 전날부터 당일까지 열려요.`
     (○○ = 제목 장소 `titlePlace`, 없으면 `place`. 날짜가 비면 날짜 부분을 뺀다.)
  3. 휴대폰(`(pointer: coarse)`): `navigator.share({ text })` — **글만**(기록장 #36: 파일과 함께 보내면 카톡이 글을 버린다). 취소하면 아무 일 없음.
     PC: 클립보드에 복사 + 알림 "링크를 복사했어요 — 카톡 대화창에 붙여 넣으세요"(견적서 PC 보내기와 같은 방식).
  4. 확정이 아니면 링크는 만들고 알림을 더한다: "확정이 되어야 담당자에게 보여요".

## 시험 (고치기 전에 실패하는 것부터)

- `staff_view`: 보이는 칸 · 안 보이는 칸(그림 · 미확정용 · 인쇄 표시 없음), 금액 있음, 둘 다 빈 품목 줄 빠짐, L → R 순서.
- `sync_staff_sheets`(가짜 저장소): 오늘 · 내일 + 확정 + 링크 있는 것만 올림 / 미확정 · 링크 없음 · 모레 · 어제는 안 올림 / 안 바뀐 것은 다시 안 씀 / 범위 밖은 지움.
- `office_agent`: 담당자 내역서 단계가 실패해도 PDF · 백업은 돈다.
- 보안 규칙(시험 프로젝트에 실제로): 로그인 없이 `staffSheets/{암호}` 읽힘 · 목록 안 됨 · 쓰기 안 됨.
- 내역서 화면(Playwright, 시험 프로젝트): [담당자 링크] 를 두 번 눌러도 같은 링크, `updatedAt` 그대로, PC 클립보드 글 모양.
- 담당자 화면(Playwright): 가짜 한 장으로 칸이 다 보임, 그림 · 미확정 칸 없음, 없는 암호 안내, 저장소를 고치면 화면이 바뀜.
- 담당자 화면 잘림(Playwright): 위 "휴대폰에서 잘리지 않게" 의 긴 가짜 자료로 **360px · 390px · 글자 1.3배** 모두 오른쪽 끝을 넘는 요소 0, 가로 스크롤 0.
  대조: 일부러 폭 600px 상자를 넣은 화면에서는 같은 검사가 걸려야 한다(검사 도구가 실제로 잡는지).
- 실제로 켜기 전에 담당자 화면 사진(360px · 390px, 긴 가짜 자료)을 사장님께 보여 드린다.

## 내보내는 순서 — 되돌리기 어려운 것은 바로 앞에서 다시 묻는다

1. 코드 · 시험 — 자동 저장으로 올라간다. 규칙을 올리기 전에는 담당자 화면이 읽기 실패 → 안내 글만 보인다(해 없음).
2. 보안 규칙: 시험 프로젝트에 먼저 올려 시험 → **실제 올리기 직전에 사장님께 묻는다.** 올리기 전에 실제 규칙과 저장소의 마지막 파일을 비교한다(기록장 #46).
   `npx firebase-tools@15.34.0 deploy --only firestore:rules --project test`(실제는 `default`)
3. 사무실 PC 프로그램 다시 켜기 → 켜진 시각 확인 → 기록에 "담당자 내역서" 줄이 생기는지.
4. 사장님이 실제 확정 행사 하나로 [담당자 링크] → 자기 휴대폰에서 열어 본다.

## 하지 않는 것

- 단톡방 '푸드벨 일정'(`today.html`)에 넣기 · 고른 몇 명용 링크 하나 · 붙인 그림 · 담당자가 고치기 · 링크 바꾸기 단추 · 홈 화면 아이콘 · 담당자에게 저절로 보내기 · 사흘 이상 앞 행사 보이기.
