# 푸드벨 브랜드 가이드

전통 제례·시제 및 단체 행사 맞춤 출장음식 브랜드. 핵심 인상은 **정중함·격식·신뢰**이며,
싸구려 전단지 느낌이나 과한 형광색·이모지 남발은 브랜드를 훼손한다.

> 상호는 **푸드벨**이다. `예도(禮道)`는 이전 상호이며, 새로 만드는 결과물에는 쓰지 않는다.
> 다만 사용자가 "예도"라고 부르면 같은 브랜드를 가리키는 것으로 보고 이 가이드를 적용한다.

> **기준은 살아 있는 사이트다.** 실제 값은 `c:\galleypark\css\style.css` 의 토큰과
> `c:\galleypark\index.html`. 이 문서와 코드가 다르면 **코드가 맞다** — 코드를 확인하고 이 문서를 고친다.

**Keywords**: 푸드벨, 푸드벨견적서, 출장음식, 제례, 시제, 브랜드 색, 브랜드 톤, 상차림, 견적서, 썸네일, 랜딩페이지, 예도(옛 상호)

- 버건디 `#6E1E2B`는 **강조 전용**(버튼·인장·합계 띠). 넓은 면적 배경으로 쓰지 않는다.
- 골드는 **선·테두리·작은 아이콘·섹션 제목 눈금선**에만. 큰 글씨엔 쓰지 않는다.
- 한 화면에 버건디 + 골드를 동시에 **강조**로 쓰지 않는다. 골드는 장식, 버건디가 주인공.
- **섹션 제목 아래 금색 2px 눈금선**이 브랜드 시그니처다 (`.section-title::after`, 폭 44px).

## 2. 서체 (Typography)

```
제목 / 브랜드명 : 'Gowun Batang'(곱은바탕), serif   — 400 / 700
본문 / UI       : 'Pretendard', 'Noto Sans KR', sans-serif — 400 / 500 / 600 / 700
```

로드 링크 — **기준 파일은 `c:\galleypark\index.html` 의 `<head>`** 다. 아래는 그 사본이다.

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Gowun+Batang:wght@400;700&display=swap" rel="stylesheet">
<link rel="preconnect" href="https://cdn.jsdelivr.net" crossorigin>
<!-- 본문 글꼴 — 통짜(약 2.3MB) 대신 쓰는 글자만 조각으로 받는 dynamic-subset -->
<link rel="stylesheet" as="style" crossorigin href="https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/static/pretendard-dynamic-subset.css">
```

**통짜 `pretendard.min.css` 를 쓰지 않는다** — 약 1.95MB 를 더 받게 된다.

### 환경마다 쓸 수 있는 글꼴이 다르다

| 만드는 곳 | Pretendard | 대신 쓸 것 |
|---|---|---|
| 웹사이트 (`index.html`, 견적서) | ○ jsDelivr 로드됨 | — |
| 아티팩트 · 클로드 디자인 캔버스 | **✗ 막힘** (구글 폰트 외 외부 스타일시트 차단) | 구글 폰트 `Noto Sans KR` |

아티팩트·캔버스에서 본문이 Pretendard 로 안 나오는 것은 **고장이 아니라 정상**이다.
원인을 다시 찾지 말고 바로 Noto Sans KR 로 간다. 곱은바탕은 구글 폰트라 어디서나 된다.

### 글자 굵기 — 세 단계만 쓴다
| 토큰 | 값 | 용도 |
|---|---|---|
| `--weight-normal` | 400 | 본문·설명문·주석·푸터 안내·입력칸 — 화면 대부분 |
| `--weight-medium` | 600 | 네비·버튼·탭·아이브로우·폼 라벨·강조 단어 |
| `--weight-bold` | 700 | 제목(h1~h3)·섹션 타이틀·대표 전화번호·가격·합계 |

곱은바탕은 400·700만 있으므로 **명조 제목은 700**, 명조 본문은 400. 600은 Pretendard 전용.

규칙
- **제목은 반드시 명조(곱은바탕)**. 고딕 제목은 격식이 깨진다.
- 본문은 Pretendard, 없으면 Noto Sans KR로 폴백.
- 브랜드명은 `푸드벨` 그대로. **한자를 지어 붙이지 않는다.**
- 제례 용어의 한자 병기(`奉行 槪要`, `陳設 五列`, `見積 內譯` 등)는 격식을 위해 유지한다.
- 낙관(인장)이 필요하면 버건디(`#6E1E2B`) 정사각형에 `푸 / 드 / 벨`을 세로로, 곱은바탕 700.
- 본문 행간 1.7 이상. 제례 관련 문서는 여백이 곧 격식이다.

## 3. 톤앤매너 (Voice)

**지향**
- 정중한 존댓말. "모시겠습니다", "정성껏 준비합니다", "예를 다해"
- 구체적 숫자로 신뢰 확보: 인원, 시간, 지역, 가격 범위
- 핵심 3축을 반복: **전국 출장 / 정시 도착·현장 세팅 / 규모별 1:1 맞춤 견적**

**금지**
- 느낌표 남발, 이모지 도배 (특히 제례·상례 맥락)
- "대박", "초특가", "역대급" 등 과장 표현
- 고인·유족을 가볍게 다루는 표현
- 근거 없는 최상급 ("업계 1위", "최고의")

## 5. 적용 방법

1. 결과물 종류를 파악한다 (웹페이지 / 인쇄물 / SNS / 문서).
2. 위 팔레트와 서체를 **그대로** 적용한다. 새 색을 발명하지 않는다.
3. 모바일 결과물이면 하단 고정 CTA 바(전화 + 문자)를 반드시 넣는다.
4. 완성 후 자가 점검:
   - [ ] 페이지 바탕이 미색(`#F7F2E9`)인가? (회색 아님)
   - [ ] 제목이 곱은바탕(명조)인가?
   - [ ] 강조색이 `#6E1E2B` 하나로 통일됐는가?
   - [ ] 글자 굵기가 400 / 600 / 700 세 단계 안인가? (전부 굵게 금지)
   - [ ] 섹션 제목 아래 금색 눈금선이 있는가?
   - [ ] 상호가 `푸드벨`인가? (옛 상호 `예도`, 옛 접두사 `YD-` 가 남아 있지 않은가)
   - [ ] 전화번호 `010-5353-3477`이 눈에 띄는가?
   - [ ] 제례 맥락에 어울리는 정중한 문장인가?
   - [ ] **쓴 사진을 실제로 열어서 확인했는가?** 영정사진, 이름·생몰년이 보이는 묘비,
         얼굴이 그대로 드러난 사적인 사진이 없는가?
         → **대체 텍스트나 파일 이름으로 판단하지 않는다.** "가정 제사상"이라고 적혀 있어도
         실제로는 다른 사진일 수 있다. 제례·상례 사진은 유족의 개인정보와 바로 이어진다.
   - [ ] **촬영정보(EXIF·GPS)가 지워졌는가?** 묘소 사진의 위치정보는 곧 묘소 위치 공개다.
         `사진용량줄이기.py` 를 거치면 빠지지만, 그 도구를 안 거치고 올린 한 장이면 샌다.
   - [ ] 사이트 주소를 넣었다면 4절의 현재 주소(`https://foodbell.kr/`)인가?
   - [ ] 주소를 넣었다면 4절 "어디에 어느 주소를 쓰나" 표에 맞는 주소인가?
   - [ ] 링크 미리보기 카드를 건드렸다면 **실제로 카톡에 보내 눈으로 확인했는가?**

### 링크 미리보기 카드 (`og:image`) — 카톡으로 주소를 보낼 때 뜨는 그림

이 스킬은 "SNS 카드"를 대상이라 적어두고도 오랫동안 규격이 없었다. 그 사이
사이트의 `og:image` 는 **825×830 정사각형**이었고, 카톡 큰 카드에서 위아래가
잘려 **고임 상차림의 윗부분이 날아가고 있었다**(2026-09-23 발견·교체).
아무도 몰랐던 이유는 단순하다 — 그 카드를 브랜드 결과물로 점검한 적이 없다.

| 항목 | 값 |
|---|---|
| 크기 | **1200×630 (1.91:1)** — 정사각형은 위아래가 잘린다 |
| 최소 | 폭 600px 이상, 용량 5MB 이하 |
| 같이 넣을 태그 | `og:image:width` / `height` — **없으면 카카오가 작은 썸네일로 띄운다** |
| 그 밖에 | `og:url`, `og:type`, `og:site_name`, `og:image:alt`, `twitter:card` |
| 현재 파일 | `images/og-card.jpg` (원본 `hero-table.jpg` 1600×842 를 맞춘 것) |

- **사진을 바꿀 때는 파일 이름도 바꾼다.** 카톡은 사진을 세게 캐시한다.
- **페이지 쪽 캐시는 파일 이름으로 못 푼다.** 카카오 디버거에서 비운다:
  `https://developers.kakao.com/tool/clear/og` (카카오 로그인 필요. 주소는
  `https://` 까지 **정확히** 넣는다 — `foodbell.kr` 만 넣으면 엉뚱한 걸 비운다.)
- 비운 뒤 **카톡 "나에게 보내기"로 먼저 확인**하고 손님께 보낸다.
- 제목·설명을 바꿀 때도 이 캐시 비우기를 해야 반영된다.

### QR 코드

파일은 `c:\galleypark\design\qr\` 에 있다(저장소에 있지만 `design/` 이라 손님
주소로는 안 열린다). **인쇄소에 전할 사항은 같은 폴더의 `읽어보기.md` 가 주인이다
— 여기서 되풀이하지 않는다.** 이 절은 브랜드 판단만 적는다.

| 용도 | 파일 | 오류정정 |
|---|---|---|
| 명함·견적서 | `qr-명함.png` | Q (25%) |
| 현수막·입간판 | `qr-현수막.png` / `qr-현수막-낙관.png` | H (30%) |
| 화면·카톡 | `qr-화면.png` | M (15%) |

**가운데 낙관은 오류정정 H 일 때만 넣는다.** 낮은 등급에서 가운데를 덮으면
못 읽는다.

### 브랜드 요소를 넣을지는 "최종 표시 크기"로 판단한다

같은 낙관을 og 카드에서는 빼고 QR 에는 넣었다. 앞뒤가 안 맞아 보이지만 같은
기준이다 — **손님 눈에 닿는 크기.**

- og 카드의 낙관: 1200px 중 107px. 숫자로는 넉넉하지만 카톡이 카드를 300px 로
  띄우면 **30px 얼룩**이 된다. 게다가 카드는 상호를 **글자로 따로 띄워준다.**
- QR 의 낙관: 명함 2cm·현수막 30cm 로 인쇄되니 또렷하다.

**만든 크기로 보지 말고, 놓일 자리의 크기로 본다.** 썸네일·파비콘·SNS 카드처럼
줄어드는 자리에서는 글자가 든 요소를 넣기 전에 줄여서 확인한다.

### 사진 규칙을 새로 만들거나 강화했다면 — 이미 게시된 것도 되짚는다

이 절의 사진 규칙은 **새로 만드는 결과물에만** 적용돼 왔고, 규칙이 생기기 전에 이미
올라간 사진은 한 번도 이 기준으로 검사되지 않았다. 나중에 게시 중인 84장을 훑어 보니
**얼굴·차량 번호판·비석의 성씨와 본관이 실제로 게시돼 있었다**(2026-09-14 발견,
09-15 가림 처리). 규칙이 있었는데도 걸러지지 않은 이유는 단순하다 — 규칙이
"앞으로"만 보고 있었기 때문이다.

**규칙을 만들거나 바꾸는 것 자체를 "기존 게시물 전체 재점검"의 방아쇠로 삼는다.**
점검 절차는 `foodbell-site-dev` 7절에 있다. 그리고 공개 저장소에서 **"지웠다"는
"안 보이게 했다"와 다르다** — 지운 사진도 git 기록에서 그대로 꺼낼 수 있다.
