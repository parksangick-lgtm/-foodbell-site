# 5번 — 바이브코딩 작업 옵시디언 저장

홈페이지 만드는 작업이 끝난 뒤, **그날 한 일 전부**를 옵시디언 학습 노트 한 장으로 남긴다.

## 이 스킬의 목적

사용자는 바이브코딩을 **배우는 중**이다. 그래서 이 노트는 "작업 기록"이 아니라
**나중에 다시 읽고 배우는 교재**여야 한다. 세 달 뒤에 읽어도 무슨 일이 있었는지,
왜 그렇게 했는지 알 수 있게 쓴다.

저장 위치는 사용자가 이미 쓰고 있는 **`바이브코딩-위키`** 폴더다. 그 안에는
`01-출장음식사이트-사진갤러리-만들기`, `02-웹개발-학습로드맵` 처럼 **번호가 붙은
노트**가 순서대로 쌓여 있다. 새 노트도 **그 번호를 이어받아** 같은 방식으로 넣는다.

## 1단계 — 작업 내용 모으기

기억에만 의존하지 말고 **실제 작업 폴더를 확인**한다. 대화에서 이미 아는 내용이라도
아래를 돌려서 빠진 게 없는지 맞춰본다.

```bash
git log --oneline -20              # 오늘 만든 커밋
git diff --stat HEAD~1             # 뭐가 얼마나 바뀌었나 (커밋이 있을 때)
git status --short                 # 아직 커밋 안 한 것
ls -R                              # 파일 구조 (node_modules 등은 빼고)
```

git을 안 쓰는 폴더면 `ls -R` 과 대화 내용으로 정리한다.

모을 것:

- 무엇을 만들었나 (화면/기능 단위로)
- 어떤 파일이 새로 생기고 어떻게 바뀌었나
- 중간에 난 **에러 메시지와 그걸 어떻게 고쳤는지** ← 학습에서 가장 중요하다
- 사용자가 물어봤던 것, 헷갈려 했던 것

## 2단계 — 노트 본문 쓰기

아래 틀을 그대로 쓴다. 내용이 없는 항목은 통째로 뺀다(빈 제목만 남기지 않는다).

```markdown
## 한 줄 요약
(오늘 무엇을 만들었는지 한 문장)

## 오늘 만든 것
- 화면이나 기능 단위로 3~6개. 각각 한 문장.

## 파일 구조
(만들거나 고친 파일만. 트리 모양으로)
```text
회사홈페이지/
├── index.html      ← 첫 화면
└── style.css       ← 색과 글씨 꾸미기
```

## 핵심 코드
(오늘 바뀐 것 중 **핵심만** 2~4덩어리. 파일 전체를 붙여넣지 않는다.)

### index.html — 메뉴 버튼 부분
```html
(코드)
```
**무슨 뜻이냐면**: (초등학생에게 설명하듯 2~3줄)

## 막혔던 것과 해결법
| 무슨 일이 있었나 | 왜 그랬나 | 어떻게 고쳤나 |
| --- | --- | --- |
| (화면에 나온 에러 메시지 그대로) | (원인) | (해결 방법) |

## 배운 것
- 새로 알게 된 것 3~5개. 어려운 말에는 괄호로 뜻을 붙인다.
  예: "CSS(웹페이지의 색과 모양을 정하는 언어)로 버튼 색을 바꿨다"

## 다음에 할 일
- [ ] 다음 작업 때 이어서 할 것 2~4개 (체크박스로)

## 관련 노트
[[02-웹개발-학습로드맵]] · [[08-에러대응법]]
```

### 쓸 때 지킬 것

- **쉬운 말로 쓴다.** 어려운 용어는 반드시 괄호로 뜻을 붙인다.
- **핵심 코드만.** 파일 전체 코드는 넣지 않는다. 바뀐 핵심 부분만 잘라서 넣고,
  나머지는 "파일 구조"에 이름만 적는다.
- **에러는 화면에 나온 그대로** 적는다. 나중에 같은 에러를 검색해서 찾을 수 있어야 한다.
- 코드 블록에는 언어를 붙인다(```html, ```css, ```js, ```bash).
- **관련 노트는 실제로 있는 노트만** 링크한다. 폴더를 먼저 확인해서 이름을 맞춘다.
  없는 이름을 링크하면 옵시디언에 빈 노트가 생긴다.
- 지어내지 않는다. 실제로 한 것만 쓴다.

## 3단계 — 옵시디언에 저장

노트 본문을 임시 파일에 쓴 뒤 저장 스크립트를 부른다.

**먼저 스크립트를 찾는다.** 아래 순서로 있는 것을 쓴다.

1. `~/.claude/skills/obsidian-save/obsidian_save.py` ← 설치돼 있으면 어느 폴더에서든 이걸 쓴다
2. `src/obsidian_save.py` ← 유튜브 요약 저장소 안에서 작업 중일 때
3. 둘 다 없으면 아래 "스크립트를 못 찾을 때" 로 간다

```bash
python ~/.claude/skills/obsidian-save/obsidian_save.py \
  --title "회사홈페이지-첫화면과-메뉴-만들기" \
  --folder "바이브코딩-위키" \
  --tags "바이브코딩,학습,HTML" \
  --auto-number \
  --file /tmp/vibe-note.md
```

### 제목 짓는 규칙 (중요)

기존 위키와 **똑같은 모양**으로 맞춘다.

- **띄어쓰기 대신 붙임표(`-`)** 를 쓴다 → `회사홈페이지-첫화면과-메뉴-만들기`
- **번호는 직접 붙이지 않는다.** `--auto-number` 가 폴더를 보고 다음 번호(`17-`, `18-`)를
  알아서 앞에 붙인다.
- `--date-prefix` 는 쓰지 않는다. 날짜는 노트 속성의 `created` 에 남는다.

| 좋은 예 | 나쁜 예 |
| --- | --- |
| `회사홈페이지-첫화면과-메뉴-만들기` | `2026-09-06 회사홈페이지 첫 화면` |
| `사진갤러리-반응형으로-고치기` | `17-사진갤러리 반응형` (번호를 직접 붙임) |

### 폴더와 태그

- **폴더**: 항상 `바이브코딩-위키` (`.env` 의 `OBSIDIAN_VIBE_FOLDER` 가 있으면 그 값)
- **태그**: `바이브코딩`, `학습` 은 항상. 여기에 쓴 기술을 더한다(`HTML`, `CSS`, `React` 등)

### 볼트 경로

스크립트가 옵시디언 설정에서 **자동으로 찾는다.** 사용자에게 경로를 묻지 않는다.
찾는 순서는 `--vault` > `OBSIDIAN_VAULT` > `~/.claude/obsidian_vault.txt` >
옵시디언 설정 파일 자동 탐색이다.

"볼트를 찾지 못했습니다" 가 나올 때만 아래로 확인한 뒤 사용자에게 물어본다.

```bash
python ~/.claude/skills/obsidian-save/obsidian_save.py --list-vaults
```

### 스크립트를 못 찾을 때

스크립트를 어디에서도 못 찾으면 **볼트 폴더에 마크다운 파일을 직접 쓴다.**
옵시디언 볼트는 그냥 폴더라서 그래도 된다.

1. 볼트 경로를 찾는다: `~/.claude/obsidian_vault.txt` → 없으면 옵시디언 설정 파일
   (윈도우 `%APPDATA%\obsidian\obsidian.json`, 맥 `~/Library/Application Support/obsidian/obsidian.json`,
   리눅스 `~/.config/obsidian/obsidian.json`) 안의 `vaults` 목록
2. `<볼트>/바이브코딩-위키/` 를 훑어 가장 큰 번호를 찾고 +1 한다
3. `<볼트>/바이브코딩-위키/17-제목.md` 로 쓴다. 맨 위에 속성 블록을 붙인다:

```markdown
---
title: "회사홈페이지-첫화면과-메뉴-만들기"
created: 2026-09-06T14:30:00
tags:
  - 바이브코딩
  - 학습
  - HTML
---
```

파일 이름에 `\ / : * ? " < > | # ^ [ ]` 는 쓰지 않는다(옵시디언이 못 읽거나 링크가 깨진다).

## 4단계 — 보고

저장이 끝나면 이렇게 알려준다.

1. 저장된 **전체 경로**와 **붙은 번호** (예: `17-회사홈페이지-첫화면과-메뉴-만들기.md`)
2. 노트에 담은 **항목 목록** (한 줄 요약 / 핵심 코드 3개 / 배운 것 4개 …)
3. 정한 **태그**

## 주의할 점

- **클라우드(웹) 세션에서는 저장되지 않는다.** 볼트는 사용자 PC 안의 폴더라서
  클라우드 서버는 닿을 수 없다. 이때는 저장하지 말고 노트 내용을 화면에 보여준 뒤
  "내 PC에서 5번을 다시 실행하면 볼트에 들어갑니다"라고 알려준다.
- **같은 날 두 번 저장**해도 괜찮다. 번호가 하나씩 올라가고, 이름까지 겹치면
  `제목 2.md` 로 새로 만들어서 앞의 노트를 덮어쓰지 않는다.
- `.env`, API 키, 비밀번호는 **노트에 절대 넣지 않는다.** 코드에 키가 들어 있으면
  `sk-ant-...` 처럼 가린다.
